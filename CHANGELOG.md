# Changelog

## Unreleased

### Added
- **`PaperTradingService`** (`core/services/paper_trading_service.py`): reusable, Streamlit-free paper-trading orchestration workflow consuming `TradingDecision` (from `TradingPipeline`, a queued `trade_queue` signal, or a manual page entry). A validated order lifecycle (`CREATED → VALIDATED → SUBMITTED → FILLED`, or `REJECTED`/`CANCELLED`/`EXPIRED`, with `InvalidOrderStateTransitionError` on invalid transitions) replaces the legacy `PaperTrader`'s synchronous, unvalidated `buy()`/`sell()` for these workflows. Deterministic adverse slippage/commission fills (mirroring `BacktestService`'s convention), cash/position-limit/max-open-position order sizing, one-position-per-symbol weighted-average entry, stop-loss/take-profit exits (adverse-first), manual full/partial closes, realised P&L, trade-history recording, and account reconciliation (`reconcile()`). Typed models (`PaperAccount`, `PaperOrder`, `PaperPosition`, `PaperTrade`, `PaperTradingResult`, `ReconciliationResult`) and an error hierarchy (`PaperTradingServiceError` and subclasses) replace the legacy `(bool, message)` tuple convention. 100% simulated/local: no broker import, no credentials, no live order submission.
- `core/execution/paper_orders_repository.py`: small, table-scoped persistence functions for `PaperTradingService` (mirroring `trade_queue.py`/`scanner_repository.py`'s convention), including atomic fill application (`apply_entry_fill`/`apply_exit_fill` - single transaction per fill, with rollback on failure). The pre-existing `core/execution/paper_trader.py` (`PaperTrader`) is left completely untouched; `PaperTradingService` owns independent bookkeeping against the same underlying tables, reusing `PaperTrader`'s existing weighted-average-entry and cash-delta conventions for consistency.
- Additive schema changes (`core/database/database.py`, idempotent via the existing `add_column_if_missing` pattern): two new tables, `paper_orders` (the order lifecycle) and `paper_audit_events` (an audit trail); new nullable/defaulted columns on `account_state` (`realised_pnl`, `reserved_cash`), `paper_positions` (`realised_pnl`, `opened_at`, `strategy_name`, `strategy_mode`), and `paper_trades` (`order_id`, `entry_price`, `gross_pnl`, `fees`, `net_pnl`, `exit_reason`, `strategy_name`, `strategy_mode` - populated only on exit fills, turning that ledger row into a round-trip trade record). No existing table or column was renamed or removed.
- Standalone paper runtime (`core/runtime/paper_runtime.py`, `run_paper_trading`): `RuntimeRouter` now dispatches `RuntimeMode.PAPER` to it instead of returning a placeholder "not implemented" result, mirroring the scanner/backtest runtimes' shape exactly. Builds `PaperTradingService` from the new `PAPER_*` settings (`config/defaults.py`), optionally refreshes position prices/exits through an injected `price_fetch_fn` (no implicit market-data download), and processes the trade queue only when `PAPER_PROCESS_QUEUE` is explicitly enabled (defaults to `False`).
- New `PAPER_*` configuration defaults (`config/defaults.py`): `PAPER_ACCOUNT_ID`, `PAPER_STARTING_BALANCE`, `PAPER_COMMISSION`, `PAPER_SLIPPAGE`, `PAPER_MAX_OPEN_POSITIONS`, `PAPER_MAX_POSITION_PERCENT`, `PAPER_PROCESS_QUEUE` (`False`), `PAPER_ALLOW_MANUAL_CLOSE`, `PAPER_PRICE_SOURCE`, `PAPER_REQUIRE_STOP_LOSS`, `PAPER_REQUIRE_TAKE_PROFIT`.
- `pages/2_Portfolio.py`, `pages/4_Paper_Trading.py`, `pages/6_Order_Management.py` rewritten as thin UI adapters over `PaperTradingService` - no more direct `PaperTrader`/SQL access from any of the three pages. `pages/4_Paper_Trading.py` gained queued-signal display and controlled processing (select specific `trade_queue` items and process them, with an optional "hold for review before filling" mode that stops at `VALIDATED`), and an order history table. `pages/6_Order_Management.py` gained an order-review section (Fill Now / Cancel) for orders held at `CREATED`/`VALIDATED`/`SUBMITTED`.
- `pages/3_Trade_History.py` implemented (previously an empty, unimplemented file since the initial commit): a thin read-only view of completed paper trades (`PaperTradingService.get_trades()`) with a summary (total trades, win rate, total net P&L).
- Unit tests: `tests/unit/test_paper_trading_service.py` (39 tests - account init, order creation/validation/rejection, lifecycle transitions valid/invalid, slippage/commission, atomic-fill rollback, position/cash math, stop-loss/take-profit/adverse-first exits, manual close, realised P&L, reconciliation success/mismatch, queue processing enabled/disabled/isolated-per-item, import-boundary guards), `tests/unit/test_paper_runtime.py` (11 tests), `tests/unit/test_paper_database_schema.py` (4 tests - new-table/column creation, idempotent re-initialisation, additive migration over a pre-existing legacy-shaped database), and Streamlit `AppTest` page suites for all four pages (`test_paper_trading_page.py`, `test_order_management_page.py`, `test_portfolio_page.py`, `test_trade_history_page.py`).
- A paper-dispatch test added to `tests/unit/test_runtime_router.py` (`test_route_paper_mode_delegates_to_paper_runtime`), mirroring the existing scanner/backtest dispatch tests.
- **`pages/5_Trade_Queue.py` migrated to `PaperTradingService`**, eliminating the last Streamlit-page writer using the legacy `ExecutionRouter`/`PaperTrader` path. `PaperTradingService` gained one small read-only method, `get_pending_queue_items()` (a one-line delegation to the same injected `get_pending_trades` collaborator `process_queue()` already used internally - no new query logic). The page now: shows the paper account summary, lists pending queue rows, lets the user multiselect specific rows and process them via the existing `process_queue(enabled=True, queue_ids=[...], auto_fill=...)` (unchanged - already supported per-row selection, per-item failure isolation, and `EXECUTED`/`REJECTED` queue-status updates from the prior milestone), with an optional "hold for review before filling" control (`auto_fill=False`) matching `pages/4_Paper_Trading.py`, and shows recent paper orders sourced from the queue (`source_reference` starting with `"trade_queue:"`). The `Execution Mode` selector (`PAPER`/`IBKR_PAPER`/`IBKR_LIVE`) and the single-row "Approve and Execute"/"Reject Trade" buttons are removed entirely - there is no broker mode to select, and unselected rows simply stay `PENDING`. `tests/unit/test_trade_queue_page.py` added (22 tests): import-boundary/no-direct-SQL guards, pending-item rendering, selection-to-`process_queue` mapping, unselected-rows-excluded, processing-off-until-explicit-click, filled/rejected-count rendering, warning/error/service-exception rendering, hold-for-review → `auto_fill=False`, recent-orders-from-queue rendering.
- **`PortfolioService`** (`core/services/portfolio_service.py`): the authoritative, read-only portfolio analytics workflow - valuation, exposure (gross/net), allocation, position weighting, completed-trade statistics, portfolio snapshots, equity-curve/drawdown/volatility/Sharpe/Sortino performance, and reconciliation reporting. Reads directly from the same repository-level row functions `PaperTradingService` already uses (`core/execution/paper_orders_repository.py`) rather than wrapping its typed models, so it can expose richer analytics fields without changing `PaperTradingService`; reconciliation is surfaced (not duplicated) via an injected `PaperTradingService.reconcile()`. Never creates, fills, or cancels an order, never mutates cash/positions, imports no Streamlit/broker module. Typed models: `PortfolioPosition`, `PortfolioSummary`, `PortfolioPerformance`, `PortfolioSnapshot`, `PortfolioAnalysis`. Error hierarchy: `PortfolioServiceError` → `PortfolioDataError`, `SnapshotPersistenceError`.
- Additive schema change: new `portfolio_snapshots` table (`core/database/database.py`) - `id, timestamp, account_id, cash, market_value, equity, realised_pnl, unrealised_pnl, gross_exposure, position_count`. Snapshot creation is an explicit action (`PortfolioService.create_snapshot()`), never written invisibly on a read. Persistence in new `core/portfolio/portfolio_repository.py` (mirrors `paper_orders_repository.py`'s convention: flat, table-scoped functions, no ORM).
- `pages/2_Portfolio.py` rewritten as a thin, read-only analytics adapter over `PortfolioService` - the page no longer computes allocation, average position, or largest position itself. It retains `PaperTradingService` only for the one state-changing action ("Refresh Position Prices"), and gained an equity curve, drawdown/Sharpe display, completed-trade statistics, an insufficient-history warning, a reconciliation success/mismatch banner, and an explicit "Create Portfolio Snapshot" button.
- `pages/4_Paper_Trading.py` cleanup: pending-queue reads now go through `PaperTradingService.get_pending_queue_items()` instead of importing `core.execution.trade_queue.get_pending_trades` directly - every active paper-trading page now shares the same read/write service boundary.
- `core/runtime/paper_runtime.py`'s terminal summary (cash, equity, position count, realised/unrealised P&L) now comes from `PortfolioService.get_summary()` instead of being re-derived directly from `PaperTradingService`, so the runtime never duplicates portfolio equations. `PaperTradingService` gained a public read-only `db_path` property so a default `PortfolioService` can be built against the exact same database as the runtime's `PaperTradingService` instance (an injected `portfolio_service` is also accepted, matching the existing `service`/`price_fetch_fn` injection pattern).
- Unit tests: `tests/unit/test_portfolio_service.py` (46 tests - empty/single/multiple-position summaries, cost basis/market value/unrealised P&L/realised P&L, equity/total P&L/total return, gross/net exposure/cash %/weights/largest/average position, zero-equity safety, completed-trade statistics, snapshot creation/reload/chronological order, equity curve/drawdown/insufficient-history warnings, reconciliation success/mismatch, data-read error translation, import-boundary guards), full rewrite of `tests/unit/test_portfolio_page.py` (22 tests), two new/updated snapshot-schema tests plus a snapshot-repository round-trip integration test in `tests/unit/test_paper_database_schema.py`, and updated `tests/unit/test_paper_trading_page.py`/`tests/unit/test_paper_runtime.py` for the queue-read and `PortfolioService`-sourced-summary changes.
- **Broker interface + `PaperBroker` adapter** (`core/broker/`): a stable, broker-neutral `BrokerInterface` (`ABC`) contract ahead of any external broker integration - `broker_name`, `is_connected`, `connect`/`disconnect`/`get_connection_status`, `get_account`, `get_positions`, `get_open_orders`, `get_order`, `submit_order`, `cancel_order`, `get_fills`. Typed models (`core/broker/models.py`): `BrokerConnection`, `BrokerAccount`, `BrokerPosition`, `BrokerOrderRequest`, `BrokerOrder`, `BrokerFill`, and stable enums `BrokerEnvironment`, `BrokerConnectionState`, `BrokerOrderSide`, `BrokerOrderType`, `BrokerTimeInForce`, `BrokerOrderStatus`. Controlled error hierarchy (`core/broker/errors.py`): `BrokerError` → `BrokerConnectionError`, `BrokerValidationError`, `BrokerOrderRejectedError` (reserved, unused by `PaperBroker`), `BrokerOrderNotFoundError`, `BrokerCancellationError`, `BrokerUnsupportedOperationError`. `PaperBroker` (`core/broker/paper_broker.py`) is the first (and only) concrete adapter: it delegates every operation to the existing `PaperTradingService`/`PortfolioService` - `submit_order` builds a minimal `TradingDecision` and calls `create_order_from_decision()` unmodified, `cancel_order` calls the existing `cancel_order()` unmodified, `get_account`/`get_positions` delegate to `PortfolioService`, and `get_fills` reads directly from the existing `paper_orders_repository.get_trade_rows()`. Business-rule rejections (insufficient cash, etc.) return `BrokerOrder(status=REJECTED, rejection_reason=...)`, matching `PaperTradingService`'s own convention; malformed requests raise `BrokerValidationError`/`BrokerUnsupportedOperationError` before any service is called. Connection state (`connect()`/`disconnect()`) is a pure in-memory simulation - no socket, thread, process, or network call is ever created, and nothing is persisted to the database; both are idempotent, and every account/order operation raises `BrokerConnectionError` while disconnected. A small optional factory (`core/broker/factory.py`, `create_broker(environment, ...)`) supports only `BrokerEnvironment.PAPER`, raising `BrokerUnsupportedOperationError` for anything else. Two small additions to `PaperTradingService`: `get_order(order_id)` and `get_open_orders()` (both thin wrappers over existing repository reads); no other existing service, page, or runtime was changed, and `PaperBroker` has zero dependency on the legacy `ExecutionRouter`/`PaperTrader` (statically verified). Not wired into any Streamlit page or runtime mode - this milestone establishes and tests the abstraction only. Unit tests: `tests/unit/test_broker_models.py` (35 tests - ABC instantiation, enum stability, model normalisation/serialization, import-boundary guards) and `tests/unit/test_paper_broker.py` (69 tests - connection semantics, account/position mapping with no double-counted unrealised P&L, order submission/rejection/validation, cancellation, fills, no-network-call and no-real-database isolation checks), plus 4 new tests for `get_order`/`get_open_orders` in `tests/unit/test_paper_trading_service.py`.

### Changed
- `RuntimeRouter._NOT_YET_IMPLEMENTED_MODES` no longer includes `paper` (it now has a real standalone runtime, dispatched lazily inside `route()` exactly like `scanner`/`backtest`); only `research` remains a placeholder.
- `tests/unit/test_runtime_router.py`'s placeholder-mode parametrized test no longer includes `RuntimeMode.PAPER` (expected edit, not a regression - `paper` is no longer a placeholder mode).
- Two latent UX bugs fixed in `pages/2_Portfolio.py`, `pages/4_Paper_Trading.py`, `pages/6_Order_Management.py` while rewriting them onto `PaperTradingService`: each page previously called `st.rerun()` unconditionally right after `st.error(...)`/`st.warning(...)`, which immediately discarded the message before a user could read it (the same pattern existed on all three original pages). `st.rerun()` is now only called after a successful action; error/warning paths leave the message visible instead.
- The same latent bug (an unconditional `st.rerun()` immediately after showing per-item warnings/errors) is fixed in the new `pages/5_Trade_Queue.py`'s "Process Selected" handler: it no longer reruns after a successful (but possibly partially-warned/errored) batch, so those messages stay visible; the pending/recent-orders tables simply reflect the post-processing state on the next interaction rather than an immediate self-triggered rerun. `pages/4_Paper_Trading.py`'s equivalent queue-processing block has the same latent issue and was **not** fixed, since that page was out of scope for this milestone (see Notes).

### Notes
- **Known limitations, intentionally deferred**: `core/execution/execution_router.py` (`ExecutionRouter`) and `core/execution/paper_trader.py` (`PaperTrader`) are no longer imported by any active Streamlit page or by `PaperBroker`, but remain in the repository, unmodified, for compatibility/later cleanup - candidates for deletion or archival in a future milestone. Trailing-stop was not carried into `PaperPosition`/`PaperTradingService` (the model spec for this milestone does not include it; `paper_positions.trailing_stop` remains legacy-only). Partial order fills are not supported (an order fills in full, at a capped quantity, or is rejected before submission); `BrokerOrderStatus.PARTIALLY_FILLED` is modelled for a future adapter but never produced by `PaperBroker`. `reserved_cash` exists on the schema/model for forward compatibility but is always `0` - there is nothing to release on `PaperBroker.cancel_order()`, documented rather than fabricated. `PortfolioService`'s equity-curve/drawdown/volatility/Sharpe/Sortino metrics are only as rich as the snapshot history a user has explicitly created (no scheduled/automatic snapshots yet); with fewer than 2 snapshots, volatility/Sharpe/Sortino are `None` with a controlled warning rather than a fabricated number. Long-only: `gross_exposure_pct`/`net_exposure_pct` are currently always numerically equal (kept as separate fields for future short-position support). `BrokerOrderType.LIMIT`/`STOP` and `BrokerTimeInForce` are modelled but not enforced/supported by `PaperBroker` (only `MARKET` orders, `time_in_force` accepted but ignored). No sector/asset-class metadata or benchmark attribution. Only `PaperBroker` exists - no IBKR/Alpaca/OANDA adapter.
- **`PaperTradingService` is now the single Streamlit-page writer of paper account, order, position, and trade state**, **`PortfolioService` is now the single authoritative read/analytics layer**, and **`BrokerInterface`/`PaperBroker` establish the single broker-facing contract** future adapters will implement - no active page performs direct SQL, calls `PaperTrader`, routes through `ExecutionRouter`, or computes portfolio statistics itself, and `PaperBroker` duplicates no order-lifecycle, fill, or analytics logic already owned by `PaperTradingService`/`PortfolioService`.
- No broker connection, credentials, network call, or live order submission exists anywhere in this change. `RuntimeMode.LIVE` remains hard-disabled.
- The pre-existing 218 tests in `tests/unit/` all continue to pass unmodified except the one expected `test_runtime_router.py` edit described earlier; the repository now has 508 tests in `tests/unit/`. The 9 orphaned root-level `test_*.py` scripts (pre-existing collection errors, unrelated to this milestone) are unaffected.

- **`BacktestService`** (`core/services/backtest_service.py`): reusable, Streamlit-free historical-backtesting workflow, reusing `TradingPipeline.evaluate()` per historical bar exactly as `ScannerService` reuses it per symbol. For every bar `t`, evaluates the pipeline on `data.iloc[:t+1]` only (anti-lookahead), and on a BUY decision opens a discrete long position at the next bar's Open, sized/stopped/targeted using `TradingPipeline`'s existing ATR-based risk-engine output. Stop-loss/take-profit are checked every bar from entry onward using that bar's High/Low (adverse-first same-bar collision assumption); any position still open at the final bar is force-closed at the final close. Supports both `ScanStrategyMode.SINGLE` and `ScanStrategyMode.VOTING`, inheriting the strict-majority voting-regime rule, alpha filtering, and risk controls with no new formula. New typed models: `BacktestRequest`, `BacktestTrade`, `BacktestResult`. Computes its own equity curve and metrics (final equity, total/annualised return, volatility, Sharpe, Sortino, max drawdown, win rate, profit factor, expectancy, total trades, average win/loss, exposure, fees, and a buy-and-hold benchmark) directly from the simulated trades, since the pre-existing `core/analytics/performance.py` return-multiplier model never supported stops/targets/sizing/voting and could not satisfy the new trade contract. Performs no persistence, no broker/live calls, and no market-data downloading beyond the injected collaborator.

### Changed
- `RuntimeRouter._NOT_YET_IMPLEMENTED_MODES` no longer includes `backtest` (it now has a real standalone runtime, dispatched lazily inside `route()` exactly like `scanner`); `research` and `paper` remain placeholders.
- `ScannerService` (`core/services/scanner_service.py`) no longer imports or directly invokes the strategy engine, voting engine, indicator pipeline, regime detector/filter, alpha scorer/grader, or risk calculators. It now downloads market data, builds a `TradingPipelineRequest` per symbol, and delegates the decision to an injected `TradingPipeline` (constructor parameter `pipeline`, defaulting to `TradingPipeline()`), mapping the returned `TradingDecision` into the existing `SymbolScanOutcome`. Symbol iteration, per-symbol exception isolation, progress callbacks, persistence, trade-queue writes, ranking, and scan statistics all remain in `ScannerService`, unchanged. The public `ScannerService`/`ScanRequest`/`ScanResult`/`ScanStrategyMode` API used by `pages/1_Live_Scanner.py` and `core/runtime/scanner_runtime.py` is unaffected; only `ScannerService.__init__`'s fine-grained collaborator parameters (`strategy_fn`, `voting_fn`, `indicator_pipeline_fn`, `regime_detector`, `regime_allowance_fn`, `alpha_score_fn`, `alpha_grade_fn`, `queue_eligibility_fn`, `stop_loss_fn`, `take_profit_fn`, `position_size_fn`) were replaced by the single `pipeline` parameter — tests inject fakes into `TradingPipeline` instead.

- `RuntimeRouter._NOT_YET_IMPLEMENTED_MODES` no longer includes `scanner` (it now has a real standalone runtime); `research`, `backtest`, `paper` remain placeholders.
- `tests/unit/test_scanner_service.py`'s forbidden-import guard no longer forbids `core.voting`: `ScannerService` is now required to invoke the voting engine directly (this restriction only applied while voting was explicitly deferred).

### Notes
- Live mode is hard-disabled: `RuntimeRouter` always raises `LiveModeDisabledError` for `live`. Nothing added in this change submits broker orders.
- `BacktestService` performs no persistence: backtest results are returned in-memory only, and the SQLite schema is unchanged (no new tables).
- Standalone `research`/`paper` runtime services remain not yet implemented; the router still returns a controlled "not implemented" result for them.
- The Streamlit dashboard (`streamlit run dashboard.py`) remains a separate entry point; `ScannerService` has no Streamlit dependency.
- Scanner-result persistence and trade-queue writes remain delegated to the existing `save_scanner_results` and `save_buy_signals_to_queue` functions; `ScannerService` does not duplicate or alter their database logic. **The `scanner_results` database schema is unchanged** — voting metadata (vote score, buy/total votes, per-strategy votes) is therefore available in memory and in the ranked table only, and is not persisted.
